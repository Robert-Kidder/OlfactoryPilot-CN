# OlfactoryPilot-CN UX 设计说明

## 1. 设计目标

界面服务于实验操作，不做营销式展示。用户打开软件后应能马上判断硬件是否安全、当前处在哪个实验步骤、下一步可以做什么。所有主要文字使用简体中文，技术名词可保留英文缩写。

## 2. 全局布局

- 方案 B V3 是当前唯一手动实验设计基线，最终产品不提供新旧界面切换。
- 顶部：产品名称、当前位置、设备连接状态、设置入口和始终可见的“全局停止”。
- 主区域：实时气流图与实体控制台式操作区。
- 手动实验控制台：T/A/B/C 流量、供气、固定 2×10 机外气口矩阵、刺激时长和“释放气味”。
- 辅助页面：文件/记录、清洗、设置与开发者信息；开发者信息默认折叠。
- 当前不显示呼吸波形、呼吸阈值、呼吸触发或相关占位入口；未来有硬件和明确需求时重新规划。
- 自动实验属于未来范围，不在当前导航中提供未实现入口。

## 3. 视觉规范

- 字体：Windows 默认中文字体优先，建议 Microsoft YaHei 或系统等效字体。
- 基础字号：12px 到 14px，面板标题可略大。
- 背景：浅灰工作台风格，避免装饰性渐变和夸张色块。
- 危险色：红色，用于低气流、急停、硬件错误。
- 安全/通过：绿色，用于连接成功、安全状态和阀门开启状态。
- 警告：黄色或橙色，用于待确认、临界状态和非阻断风险。

## 4. 页面要求

### 手动实验页（方案 B V3）

- 固定显示机外气口 1–20，不根据“10/20 通道变体”改变布局；当前未接入位置变灰且不能产生硬件 intent。
- 可用气口显示机外编号和可选显示名称；“可用、已选择、实际开启、故障”必须是不同状态，不能只靠一种颜色表达。
- 当前初始化可用位置为 2/4/6/8/12/14/16/18，但界面只消费 HardwareProfile，不得在 View 中写死。
- T 总流量、A 样品流量、C 真空和刺激时长支持直接输入与步进；B 主气流只读显示 `T-A`。
- 供气和释放按钮只发送 intent；按钮文案、使能、倒计时和完成状态全部由 immutable Snapshot 驱动。
- 手动刺激从全部目标 open receipt 的共同就绪时刻起算，由 `ActuationWorker` 自动关闭；UI 定时器仅刷新显示。
- 气流图必须准确标注当前实际可观测量。只有 A 路 telemetry 时，不得称为 A+B 总流量，也不得显示未经观测证明的“稳定”。
- 常规连接和可恢复错误使用页面内状态卡，避免重复、无意义的 modal；严重安全故障才允许阻断式提示。

### 清洗页

- 显示清洗步骤、当前通道、剩余时间和是否允许中止。
- 显示 maintenance lease、记录就绪、停止收敛和恢复要求；不得只根据按钮状态推断硬件可用。
- 中止或失败时显示“正在安全关闭”；只有 A 清零、三通阀安全路线、气味阀收敛和 owner handoff 满足当前安全计划后才显示“已安全停止”。
- maintenance bundle 失败时明确显示数据已隔离、硬件采取的安全动作和用户下一步，不得显示为清洗完成。

### 选项页

- 提供可视化 HardwareProfile：固定列出机外气口 1–20，并配置“机外气口 → 内部控制阀位 → NI 线路”、显示名称、启用状态和验证状态。
- 普通视图使用机外气口和内部阀位术语；NI target、极性与原始 receipt 放在高级/开发者区域。
- 只有设备断开、无活动 session/maintenance/lease、气路处于已确认安全状态且 owner 已交接时，配置保存和气口验证入口才可用；service 层必须重复执行同一门禁。
- 保存过程显示“校验候选配置”“写入配置”“已保存，等待下次连接生效”等明确状态。
- 校验或写入失败时说明旧配置仍有效；下一次连接失败时提供显式回滚入口，不自动切换或反复重连。
- Dev1/Dev2 显示为当前必需 USB-6001；Dev3 只在用户确认实物、NI MAX 身份和用途后允许作为本机扩展添加。
- 验证状态使用自然文案：“待验证”“验证通过 · 日期”“配置已变更，请重新验证”“验证未完成”“验证失败，请检查接线”。只修改显示名称保留验证；修改内部阀位、NI 线路或极性后要求重新验证。
- HardwareProfile 成功保存后跨启动恢复；不得用 View 私有字段、QSettings 或第二份 JSON 保存安全配置。

## 5. 文案规范

- 所有面向用户的按钮、标签、提示和错误使用简体中文。
- 错误提示要说明“发生了什么”“系统采取了什么安全动作”和“用户下一步应做什么”。
- 示例：
  - “气流不足，请检查管路后重试。”
  - “协议文件无效，第 12 行缺少 valve 字段。”
  - “写入失败，请检查磁盘空间或目录权限。”
- 颜色只作辅助，安全、警告、失败和进行中状态必须同时提供文字。
- 用户可见字符串必须通过 UTF-8 严格解码、Unicode replacement character、常见乱码和旧英文提示自动化审计；设备 ID、协议字段、扩展名和 machine key 采用显式白名单。

## 6. 可用性原则

- 安全状态始终可见。
- 危险动作必须有明确反馈。
- 不让用户猜测硬件是否已连接或阀门是否已关闭。
- 动效只提供即时操作反馈，不承担硬件时序或真实状态。
- 开发新页面时应复用集中主题和组件；新链验收后删除旧 `PreTestView`、旧 View 计时、重复状态和确认无用的弹窗/代码。
