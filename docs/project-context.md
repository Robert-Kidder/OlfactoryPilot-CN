# OlfactoryPilot 项目上下文

## 项目概述
- Windows 10/11 桌面应用，使用 Python 3.10+、PySide6 控制 NI-USB-6001/6501 与 RS232 质量流量控制器，实现嗅觉刺激硬件的安全、低抖动控制。
- 目标是替换法语 LabView 旧系统（ProgOlfacto），提供中文本地化、可重复的实验流程与数据记录。

## 目标用户与使用场景
- 主要用户：心理学研究者（简化操作）、实验室技术员（硬件控制、安全约束）。
- 场景：实验前校准呼吸信号与阈值、手动/TTL 触发气味刺激、运行 CSV/TXT 协议文件、记录原始信号与事件日志。

## 业务/产品目标
- 硬件安全：气流阈值联锁，防止无气流情况下的加热/阀门误操作；退出/急停自动安全复位。
- 硬件模拟 (新增)：提供全功能硬件模拟层 (Mock HAL)，在无物理硬件环境下支持开发、测试与演示。
- 高精度控制：<20ms 软件抖动的阀门执行，支持呼吸门控与 TTL 触发。
- 可重复性：统一的 CSV/TXT 协议文件格式，自动生成 `{Timestamp}_{Subject}_{Condition}.raw/.log`。
- 中文易用性：100% 中文界面、错误与状态提示一致且简洁。

## 范围与不包含
- 范围内：呼吸信号采集与可视化（100Hz 流、>=30 FPS 渲染）、阈值调节、手动阀矩阵（4x5，支持 10/20 通道变体）、流量控制与补偿逻辑、协议执行（手动/TTL）、清洗流程、设备与串口配置持久化、硬件模拟模式。
- 范围外：云端同步/协作、多语言支持（除中文）、移动端/网页端客户端、实验数据分析与可视化（超出基本日志）。

## 关键约束与架构基线
- 架构：MVC + Worker 线程；安全逻辑与阀控运行在专用线程；信号/槽队列连接 UI、硬件与数据记录线程。
- 性能/安全：呼吸波形 100Hz 输入、UI >=30 FPS；安全状态推送 5-10Hz，LOW FLOW 报警 <500ms；所有阀/加热器在退出/异常时关闭。
- 技术栈：PySide6、pyqtgraph、nidaqmx、pyserial；打包用 pyinstaller；依赖管理使用 poetry/pip。
- 可靠性：USB 断连需安全降级并记录；日志包含抖动指标与清洗步骤结果。
- 模拟策略：Mock HAL 拦截底层驱动调用，生成合成数据（AI0 正弦波）并模拟设备状态响应。

## 集成与外部依赖
- 硬件详细映射：
    - **NI USB-6001 (Dev1):**
        - AI0: 呼吸传感器模拟输入。
        - AI6: 外部 TTL 触发信号。
        - P0.0-P0.7, P1.0-P1.3: 驱动气味通道 1-12。
        - P1.0 (Special): 总阀驱动 (Master Valve) - 上电开启，有刺激=气味路，无刺激=补偿路。
    - **NI USB-6501 (Dev2):**
        - P0.0-P0.7: 驱动气味通道 13-20。
    - **RS232 (Alicat MFCs):** 共用一个串口，ID 分别为 A, B, C。
        - MFC A: 气味/补偿气道 (刺激时=气味流速, 无刺激=气味+排空流速)。
        - MFC B: 载气气道 (恒定流速)。
        - MFC C: 排空气道 (刺激时=0, 无刺激=排空流速)。
- 外部触发：SuperLab（TTL 触发）；文件协议（CSV/TXT）兼容遗留格式。
- 操作系统：Windows 10/11。

## 成功度量（示例）
- 安全：无因气流不足导致的加热/阀门误动作；异常退出后阀门全部关闭。
- 性能：协议执行期间阀门抖动 p95 <20ms；呼吸图形渲染 >=30 FPS。
- 可用性：核心 UI/错误提示全中文；硬件自检结果一目了然；阈值/配置可持久。
- 可重复性：协议解析错误可定位到行；会话文件命名与日志完整且自动生成。

## 风险与假设
- 假设实验室具备稳定气源与传感器校准；COM/NI 设备 ID 由用户提供且正确。
- 风险：硬件驱动或权限导致的串口/NI 设备不可用；磁盘写入失败影响日志完整性；TTL 信号质量或延迟影响协议运行。
